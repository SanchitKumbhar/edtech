# Focus Flair: Production-Ready Horizontal Scalability Architecture Report

Focus Flair has been re-architected from a single-node application into a **horizontally scalable, resilient, distributed system**. Multiple backend API instances can now run concurrently behind a load balancer with cross-instance Socket.IO synchronization, centralized Redis coordination, atomic exam lifecycle transitions, distributed rate limiting, and asynchronous background worker processing via BullMQ.

## 3. Implementation Summary

### Redis Infrastructure ([backend/config/redis.js](file:///c:/Users/Sanchit/Desktop/pg/backend/config/redis.js))
- Environment-based configuration supporting `REDIS_URL` or individual host/port/password parameters.
- Client reuse and dedicated connection segregation:
  - `redisClient`: general operations (cache, rate limiting, presence).
  - `redisPub` & `redisSub`: Socket.IO adapter and pub/sub events.
  - `getBullMQConnection()`: queue and worker connection with `maxRetriesPerRequest: null`.
- Connection lifecycle hooks with exponential retry strategy and graceful shutdown (`closeRedisConnections`).
- Resilient fallback: If Redis is unavailable, the system logs warnings and degrades gracefully (bypasses cache, uses in-memory rate limiting, executes MongoDB queries directly) without process termination.

### Socket.IO Horizontal Scaling ([backend/socket/index.js](file:///c:/Users/Sanchit/Desktop/pg/backend/socket/index.js))
- Mounted `@socket.io/redis-adapter` for transparent cross-instance event distribution.
- Added JWT socket authentication middleware extracting bearer tokens from `auth.token` or headers.
- Implemented room-based authorization:
  - `join_exam`: Examinees join `exam:${examId}`, initialize Redis presence lease, and notify admins.
  - `join_monitoring`: Verifies administrator role before admitting to `exam:${examId}:admin` and `admin:monitoring`.
  - `tab_switch`: Validates session ownership, checks deduplication lock, persists event, and emits to authorized admin rooms.
  - `heartbeat` & `disconnect`: Refreshes or removes presence leases.

### Exam Execution & Submission Hardening ([backend/controllers/exams.controller.js](file:///c:/Users/Sanchit/Desktop/pg/backend/controllers/exams.controller.js))
- **Atomic Submission (CAS):** Uses `findOneAndUpdate({ _id: sessionId, studentId, status: "active" }, { $set: { status: "submitting" } })`. Exactly one request transitions status; concurrent requests return the existing session idempotently.
- **Server-Side Deadline Enforcement:** Compares `Date.now() - session.startedAt` against `exam.durationMinutes * 60 * 1000 + 30000ms`. Rejects attempt saves after deadline with `403 Forbidden`.
- **Autosave Race Protection:** `saveQuestionAttempt` requires `session.status === "active"`. Rejects saves if `submitting`, `submitted`, or `auto_submitted`.
- **Answer Validation:** Verifies `selectedOptionId` exists in the question’s option list before calculating correctness and negative marks.

### Distributed Caching Layer ([backend/utils/cache.js](file:///c:/Users/Sanchit/Desktop/pg/backend/utils/cache.js))
- Implemented cache-aside utility with single-flight stampede protection (promise coalescing prevents duplicate database hits for concurrent cache misses).
- Applied caching:
  - **Syllabus:** Cached for 3600s (`focusflair:cache:syllabus:*`). Invalidate on `createTopic`.
  - **Leaderboard:** Cached for 120s (`focusflair:cache:leaderboard:*`). Invalidate on snapshot creation.
  - **Dashboards:** Cached for 30s (`focusflair:cache:dashboard:*`). Invalidate on exam submission.
  - **Exam Details:** Cached for 60s (`focusflair:cache:exams:*`). Invalidate on exam updates/deletion.

### Distributed Rate Limiting ([backend/middleware/rateLimiter.js](file:///c:/Users/Sanchit/Desktop/pg/backend/middleware/rateLimiter.js))
- Atomic sliding-window rate limiter using Redis Sorted Sets (`ZREMRANGEBYSCORE`, `ZADD`, `ZCARD`, `EXPIRE`).
- Configured policies:
  - `authRateLimiter`: 10 req/min per IP (login and register).
  - `examAttemptLimiter`: 120 req/min per student (autosave questions).
  - `examSubmitLimiter`: 5 req/min per student (exam submissions).
  - `apiRateLimiter`: 300 req/min general API threshold.
- Sets standard RFC headers (`RateLimit-Limit`, `RateLimit-Remaining`, `RateLimit-Reset`).

### Distributed Presence & Anti-Cheat Deduplication ([backend/utils/presence.js](file:///c:/Users/Sanchit/Desktop/pg/backend/utils/presence.js))
- Active examinees register a 45-second heartbeat lease in Redis (`focusflair:presence:${examId}:${studentId}`).
- Supports multiple tabs/devices per user using a socket ID set.
- `isTabSwitchDuplicate(sessionId, 2)`: Implements a 2-second Redis lock (`SET NX EX 2`) to eliminate false-positive misconduct increments caused by rapid consecutive OS blur/visibility events.

### Background Worker Queues ([backend/config/queue.js](file:///c:/Users/Sanchit/Desktop/pg/backend/config/queue.js), [backend/workers/examWorker.js](file:///c:/Users/Sanchit/Desktop/pg/backend/workers/examWorker.js), [backend/workers/index.js](file:///c:/Users/Sanchit/Desktop/pg/backend/workers/index.js))
- BullMQ queue `exam-processing` configured with 3 retry attempts and exponential backoff.
- Jobs:
  - `process-exam-result`: Recalculates student ranks, percentiles across all submissions, updates topic stats, and evaluates badges.
  - `leaderboard-snapshot`: Computes periodic leaderboard snapshots.
- Standalone worker runner ([backend/workers/index.js](file:///c:/Users/Sanchit/Desktop/pg/backend/workers/index.js)) can run as independent containers (`npm run worker`). Supports optional embedded worker mode during local development (`RUN_EMBEDDED_WORKER=true`).

### Database Scalability & Pooling ([backend/config/db.js](file:///c:/Users/Sanchit/Desktop/pg/backend/config/db.js))
- Configured connection pooling: `maxPoolSize: 50`, `minPoolSize: 10`, `socketTimeoutMS: 45000`, `serverSelectionTimeoutMS: 15000`.
- Added compound indexes:
  - `ExamSession`: `{ examId: 1, status: 1, scoreObtained: -1 }` (for ranking/monitoring queries).
  - `QuestionAttempt`: `{ sessionId: 1, isCorrect: 1 }` (for scoring aggregations).

### Security, Health Probes & Graceful Shutdown ([backend/index.js](file:///c:/Users/Sanchit/Desktop/pg/backend/index.js), [backend/routes/health.routes.js](file:///c:/Users/Sanchit/Desktop/pg/backend/routes/health.routes.js))
- Enabled reverse proxy trust (`app.set("trust proxy", 1)`).
- Standard security headers: `X-Content-Type-Options: nosniff`, `X-Frame-Options: SAMEORIGIN`, `X-XSS-Protection: 1; mode=block`.
- Bounded body parsers (`2mb`).
- Probes:
  - `/api/health`: Uptime and process status.
  - `/api/health/liveness`: Process liveness check.
  - `/api/health/readiness`: Verifies MongoDB connection and Redis health (returns `200` if ready, `503` if degraded).
- Graceful shutdown handles `SIGTERM` and `SIGINT`, cleanly closing the HTTP server, Socket.IO connections, BullMQ workers, queues, Redis pools, and MongoDB connections.

## 8. Known Limitations & Next Steps

1. **Long-Polling Fallback:** For environments that do not support WebSockets and fall back to HTTP long-polling, configure sticky sessions (via IP hash or cookies) on the load balancer so polling handshakes reach the same instance. Pure WebSocket connections route freely across all instances.
2. **Read Replica Routing:** If read traffic scales beyond 10,000 concurrent students, introduce secondary read preference (`readPreference: 'secondaryPreferred'`) in Mongoose for static syllabus and finished exam reviews.
3. **Cluster Monitoring:** Integrate Prometheus metrics (`prom-client`) with Grafana to visualize queue depth, Redis memory usage, and socket connection gauges in real time.
